# obix-adapter-ssr

> Previous name: `@obinexusltd/obix-adapter-ssr` — OBIX packages are named without an npm scope since decision D-102 (2026-09-29); the package, its version and its exports are unchanged.

> **Compatibility package.** `obix-adapter-ssr` is kept so that code and documents that import it keep resolving. It contains **no logic**: every export below is the export of [`obix-core-ssr`](https://github.com/obinexus/obix-core-ssr) under the old name. New code should import from `obix-core-ssr`.

Old package: npm:obix-adapter-ssr@0.3.0. Decision: `rename` (published name; listed in `obix-naming.json` (OBIX monorepo record) `legacyShims`) in `docs/recovery/migration-table.md` (OBIX monorepo record) — PUBLISHED 0.3.0 → the adapter family migrates into core (adapter-* → core-*, no name collision for ssr: see the core-* rows). The published name stays as a compat shim keeping the published exports. NOTE: any `replay` export is NOT carried into the owner (D-14)..

## `obix-adapter-ssr`

| Old name | Is |
|---|---|
| `renderDocument` | `obix-core-ssr`.`renderDocument` |
| `renderToString` | `obix-core-ssr`.`renderToString` |
| `toView` | `obix-core-ssr`.`toView` |

Types: `RenderOptions`, `RenderView`, `ServerDocument`.

**Not carried over (deliberate):**

- `ComplianceError` — D-33: see `compliance`
- `compliance` — D-33: it measures every projection against the SSR adapter as the reference — an adapter as its own oracle; the independent fold is `obix-compiler-equivalence` (`obixc equivalence`)
- `renderTrace` — D-14: folds a recorded action trace into a state — replay

**Types the old package exported that the owner does not have** (TypeScript consumers importing them must switch): `ActionContext`, `ActionFn`, `ActionTrace`, `ComplianceReport`, `ComplianceRow`, `DOPComponent`, `EffectDescriptor`, `Projections`, `ValidationResult`.

## Verification

`test/shim.test.mjs` imports both packages and asserts, for every entry point: each old name is **identical** (`===`) to the owner's export (or, for the derived `renderX`, behaves as `renderWith(createX)`); the shim exports exactly these names and nothing else; every excluded name is absent. Verified on Node 26.7 only.

## Architecture role

`obix-adapter-ssr` is a **compatibility package**: it keeps an old name resolving and contains no logic — every export is the export of [`obix-core-ssr`](https://github.com/obinexus/obix-core-ssr). New code imports from `obix-core-ssr` (or from the umbrella `obix`).

The architecture of OBIX — the package families and which packages are public API — is indexed in the umbrella: [docs/architecture.md](https://github.com/obinexus/obix/blob/main/docs/architecture.md).
